# 晋级门槛

## 必须满足

候选版本只有同时满足以下条件，才允许合并并 push 到 `main`：

```text
candidate_wallet_sharpe * candidate_wallet_calmar
>
parent_wallet_sharpe * parent_wallet_calmar
```

并且：

```text
candidate.max_relative_drawdown < 30%
```

本项目已有记录通常使用更严格的：

```text
candidate.max_relative_drawdown < 25%
```

实际实验必须在报告中写明使用哪一个门槛；不能把 `max_drawdown_account` 当成 `max_relative_drawdown`。

## 数据要求

- 父策略和候选必须使用相同数据目录、时间周期、币池、手续费、资金、杠杆和配置口径。
- 主窗口和独立早期窗口必须分别记录。
- 训练窗口、FreqAI identifier 和模型特征必须可追溯。
- 改变特征、标签或模型类必须换 identifier。
- 只改变策略退出/入场参数时，才可复用预测缓存。
- 主窗口失败时不运行没有意义的早期网格。

## 禁止晋级

- 只有 smoke 结果。
- 只有单窗口结果。
- 只比较名义收益。
- 父子窗口不一致。
- 结果依赖未记录的本地缓存。
- 存在未来函数、配置覆盖、时间错位或模型路径错误。
- Sharpe 或 Calmar 非正数。
- 回撤达到或超过 30%。

## 分支规则

- `main` 只保存已经晋级的版本。
- 通过门槛：合并并 push 到 `main`。
- 未通过：保留实验旁系分支，不合并。
- 条件晋级：只能保留为旁线候选，不进入生产 `main`。
