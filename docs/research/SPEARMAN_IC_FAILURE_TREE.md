# Spearman IC 故障树与当前模型诊断

## 1. 指标定义与优化边界

Spearman IC 衡量预测排序与真实未来标签排序的一致性：

\[
\rho_t = corr(rank(\hat y_{i,t}), rank(y_{i,t}))
\]

其中 `i` 是同一时间点的币对。交易层在同一时间快照中按 `abs(raw_prediction)` 选择候选，因此排序质量比单纯幅度误差更接近交易决策。

本项目后续把**按时间截面的 Spearman IC 均值**作为排序目标；pooled Spearman 只作为诊断指标。当前研究探针只有 BTC、ETH、BNB 三个币对，每个截面最多 3 个观测，Spearman 只能取很少的离散值，统计功效不足。因此在扩大币对或连续样本前，不把单个窗口的 IC 上升写成生产改进。

依据：SciPy `spearmanr` 对 ties、常数输入和小样本的说明（https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.spearmanr.html）；Gu、Kelly、Xiu（2020）将截面排序预测作为资产定价机器学习的核心评价对象（https://doi.org/10.1093/rfs/hhaa009）。

## 2. 故障树

```text
Spearman IC 低
├─ A. 评估对象或标签错误
│  ├─ A1 预测时点与 future label 错位
│  ├─ A2 raw return 与 volnorm 标签尺度混用/ATR 时点错误
│  ├─ A3 pooled 相关代替逐时点截面相关
│  ├─ A4 常数输入、NaN 或 ties 被静默处理
│  └─ A5 时区、重复时间戳、币对配对错误
├─ B. 数据与样本结构
│  ├─ B1 特征相对 candle 时间错位或泄漏
│  ├─ B2 训练分布与开发分布/regime/currency shift
│  ├─ B3 缺失、低方差、异常 K 线或 survivorship bias
│  └─ B4 horizon=3 造成标签重叠，独立样本数被高估
├─ C. 模型目标与模型容量
│  ├─ C1 MAE/MSE 只优化条件幅度，不直接优化排序
│  ├─ C2 early stopping 在第 0 棵树停止，输出恒定/离散
│  ├─ C3 正则过强、树太浅或学习率/树数不足，输出压缩
│  ├─ C4 容量过大、无早停导致过拟合
│  └─ C5 随机种子或训练非确定性造成 IC 波动
├─ D. 后处理与组合
│  ├─ D1 单调校准理论上不改变排序；若改变则有 ties/实现问题
│  ├─ D2 clipping、rounding、饱和造成新的并列预测
│  ├─ D3 多模型加权在交叉点改变排序或压成常数
│  └─ D4 校准使用未来标签造成泄漏
└─ E. 统计推断
   ├─ E1 pooled Simpson 抵消/混合不同币对尺度
   ├─ E2 3 个币对导致截面 rho 高度离散
   ├─ E3 相邻 horizon 标签重叠和预测自相关
   ├─ E4 regime 非平稳
   └─ E5 多窗口/多参数选择造成选择偏差
```

## 3. 当前证据逐叶判定

### 已排除或基本排除

**A2 标签尺度错误：排除。** `quant.labels.set_regression_target` 与独立的 `future_return / (TA-Lib ATR(14)/close)` 在 BTC 全历史 14,863 个有效点逐点一致，最大绝对差为 0。此前 raw-return 评估错误已经更正。

**D1 单调变换本身：不是根因。** 预测幂校准是符号保持的单调变换，理论上不应改变无 ties 的 Spearman；因此观察到的排序变化应优先归因于预测并列、模型组合交叉或 NaN 处理，而不是“幂指数本身提升了排序”。

**B3 输入完全失效：未发现。** 2025-01 BNB 训练标签标准差为 `1.199`，136 个预处理输入没有零方差列；问题发生在模型输出阶段。

### 已被数据支持的主要分支

**C2/C3 输出离散化与 ties：强支持。** 在 28,401 行三币对开发预测中，预测 ties 比例为：BNB `81.49%`、BTC `51.57%`、ETH `54.45%`。按后期 fold，ties 达 `93.73%`，该 fold 只有 593 个唯一预测。2025-01 BNB 基线 Booster 的 `best_iteration=0`，只保存 1 棵树，开发 48 点全部落入同一叶，最终预测只有 1 个唯一值，Spearman 因常数输入未定义。

**C4 无早停过拟合：同时得到支持。** 关闭早停后，2026-01 ETH 的 MAE `0.603→0.789`、RMSE `0.950→1.189`，方向 `54.2%→47.9%`，说明跑满 300 棵树会在某些状态过拟合。无早停不能全局接入。

**E3 标签重叠/自相关：强支持。** 预测序列自相关约为 BNB `.967`、BTC `.958`、ETH `.761`；标签 horizon=3 本身重叠，标签 lag-1 自相关约 `.676–.690`。因此 28,401 行不能按独立样本解释，必须使用按时间区块的 bootstrap 或 HAC 区间。

**E2 三币对截面统计功效不足：强支持。** 每个时点只有 3 个资产，截面 Spearman 只能取离散等级，且大量 ties。已有逐时点截面 IC 的均值为 `.03459`、中位数 `.5`，正值比例 `.519`，这些数不足以证明稳定排序能力。

### 尚未判定、但可验证的分支

| 分支 | 可证伪假设 | 单变量检验 | 接受标准 |
|---|---|---|---|
| C2 | 验证集早停导致后期输出恒定 | 固定数据/seed/特征，只比较早停、每轮验证曲线、预测 unique/tie | IC 与 tie率在至少 4 个独立连续窗口改善，且无严重误差退化 |
| C1 | 绝对误差目标与排序目标不匹配 | 固定全部输入，只把训练 objective 换成候选排序/相关目标 | 时间外截面 IC 的 block CI 改善；不能只看训练 IC |
| B2/F4 | regime shift 造成 IC 只在某些时期有效 | 按月、币对、波动状态分层报告 IC | 改善不能只来自一个 fold/regime |
| D3 | blend 加权造成排序交叉或 ties | 分别计算 primary、secondary、blend 的 rank/tie率，权重只用训练期拟合 | 训练外截面 IC 稳定改善且 ties 不恶化 |
| A3/E1 | pooled IC 掩盖截面 IC 或产生 Simpson 抵消 | 同时报告 pooled rho、逐时点 rho 均值/中位数和每月分布 | 指标定义一致，不能用 pooled 代替截面目标 |
| E5 | 多次窗口/参数选择造成偶然提升 | 预注册单一主指标和窗口，使用未参与选择的新窗口 | 新窗口 block CI 仍支持改善 |

## 4. 后续实验顺序

1. 先修正/固定评估：逐时点截面 Spearman、ties/常数/NaN 显式统计、按时间 block bootstrap；在此之前不比较新模型。
2. 针对 C2/C3，记录每个 pair/fold 的 `best_iteration`、验证曲线、预测标准差和 tie率，区分“第 0 棵树欠拟合”和“跑满树过拟合”。
3. 只有当输出离散化根因被确认且存在稳定修复，才研究 C1 的排序目标；排序目标实验必须保持标签、特征和切分不变，只改一个 objective。
4. 所有候选以截面 Spearman IC 为主指标，MAE/RMSE 仅作为风险护栏；不能再要求每个指标同时上升，也不能用局部窗口结果直接修改生产配置。
