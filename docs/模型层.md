# Model layer

The model layer predicts candidate risk. It does not select pairs, set leverage, or place orders.

## Current implementation

`strategies/model_layer.py` provides `XGBoostRiskModel`:

- Chronological train/validation split.
- No shuffle.
- Validation set is the only `eval_set` passed to XGBoost early stopping.
- Predictions are clipped to non-negative adverse risk by default; signed utility models explicitly set `prediction_floor=None`.
- Model identifier, model version, feature count, sample counts, best iteration, and best score are recorded.

## Smoke evidence

- Synthetic 400-row regression smoke passed.
- Real BTC 1h chain passed: 89 features, 8-bar adverse-risk labels, 343 training rows, 86 validation rows, and early stopping at best iteration 82.
- Real BTC 1h OOS diagnostics passed: 53 short validation samples with Spearman 0.366 and 33 long samples with Spearman 0.593.
- Real 15-pair OOS chain passed after feature stability fix: 30 directional models, 89 features, 69,375 validation candidates, 4,625 timestamps, and Top-3-per-side selection.
- Model-risk selection gross 8-bar directional return was 0.0504% versus 0.0470% for the no-risk-penalty control; after a 0.15% execution-cost assumption both were negative.
- Directional-utility target OOS was first measured at `-4.54%`, but that run used the risk model's default non-negative prediction floor and was invalid for signed utility. After enabling signed predictions, the normal net-edge gate selected only 8 candidates across 579 decisions and the wallet was flat. A forced Top-3 control with every level gate removed returned `-7.77%`, Sharpe `-3.087`, and maximum drawdown `8.87%`; the utility ranking itself is rejected rather than connected.
- Target-form control: pure directional-return regression returned `-10.11%` and binary positive-return classification returned `-7.65%` under the same forced Top-3 execution-aware protocol. Changing target family did not recover OOS edge.

## Feature audit

The 8-hour decision-sampled audit used the training window to form correlation clusters and the independent window only for evaluation:

- 89 model features produced 101 absolute-Spearman pairs at least 0.90.
- 56 features belonged to a multi-feature correlation cluster.
- 25 features changed Rank IC sign between the two windows; 21 stayed positive and 43 stayed negative.
- Selecting one representative from each training-window cluster reduced the input to 46 features, but the independent execution-aware OOS wallet still returned `-5.49%`, versus `-5.52%` for the all-feature baseline. The reduced model product was `1.597`, below the baseline `1.618`.

Feature clustering is therefore diagnostic evidence, not a promotion or a reason to change the production control.

The historical exponential momentum score can reach extreme finite values on long crypto windows. Model-facing momentum columns therefore use the existing signed-log compression boundary; the pair-local control signal keeps its original score columns. This prevents XGBoost input overflow without changing the control entry rule.

This is a model-chain smoke, not a trading result. OOS ranking, calibration, cross-sectional selection, cost-aware portfolio performance, and independent-window promotion remain separate gates.
