# Selection layer

The selection layer compares candidates at the same timestamp. It does not read other timestamps, set leverage, or place orders.

## Current implementation

`strategies/selection_layer.py` provides `rank_cross_sectional_candidates()`:

```text
net_edge = expected_edge - risk_penalty × predicted_adverse_risk - execution_cost
```

Long and short candidates are ranked independently. A candidate is selected only when it is within `Top-K` and its net edge meets the minimum threshold.

## Real-data smoke

The independent smoke used 54 local 1h futures files and 574 timestamps:

- Candidate rows: 14,634.
- Top-K: 3 per side.
- Selected rows: 2,490.
- Direction-aware Precision@K: 52.97%.
- Selected direction-aware future 8-bar return: 0.4608% mean.
- All-candidate direction-aware future 8-bar return: 0.3952% mean.
- Pair-set turnover proxy: 12.84% mean.

These are signal-selection diagnostics, not a fee-complete strategy backtest. Portfolio, execution, and validation layers must still run before any promotion decision.
